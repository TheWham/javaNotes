# 30 天 Java 后端面试复习执行计划

> 使用方式：这份文件只做执行清单，不替代 `Java后端面试笔记.md`。每天按当天主题回到主笔记里看对应章节，再用本文件做打卡和验收。

---

## 一、每日固定执行规则

每天固定完成 4 件事：

```text
学知识点 -> 背 1 分钟话术 -> 做 5 个追问 -> 录音复盘
```

每天结束前必须留下 4 个产出：

1. 当天 10 个关键词。
2. 5 个高频问题的 1 分钟口述答案。
3. 1 个项目结合回答。
4. 1 条今天卡壳的问题，放入错题清单。

每天建议时间分配：

| 时间 | 任务 |
|---|---|
| 60-90 分钟 | 看当天笔记内容，理解标准回答和追问点 |
| 30 分钟 | 整理 10 个关键词，不抄长段落 |
| 45 分钟 | 对着关键词口述 3 遍 |
| 30 分钟 | 练 5 个追问，每个控制在 1 分钟左右 |
| 15 分钟 | 录音回听，记录卡壳点 |

## 四、每周检查点

### 第 1 周：Java、集合、并发

验收标准：

- HashMap、ConcurrentHashMap、volatile、synchronized、CAS、AQS、线程池不能卡壳。
- 能用自己的话讲清“线程安全、原子性、可见性、锁、线程池拒绝策略”。
- 至少完成一次 30 分钟模拟面试。

### 第 2 周：JVM、Spring、MyBatis

验收标准：

- 能画出 JVM 内存结构。
- 能说出 OOM 和 CPU 飙高排查流程。
- 能讲清 IOC、AOP、Bean 生命周期、事务失效。
- 能讲清一次请求从 Controller 到 Mapper SQL 的流程。

### 第 3 周：MySQL、Redis、MQ

验收标准：

- MySQL 能讲清索引、MVCC、锁、日志和慢 SQL 排查。
- Redis 能讲清缓存问题、分布式锁、持久化、BigKey/HotKey。
- RabbitMQ 能讲清可靠性、重复消费、死信队列和消息积压。
- 回答时必须带“异常怎么办”和“怎么保证幂等”。

### 第 4 周：项目总攻

验收标准：

- 视频项目能连续讲 15 分钟。
- 交易项目能连续讲 10 分钟。
- 能回答“项目是不是真做过”“哪里体现高并发”“最难点是什么”“还有哪些优化”。
- 所有项目题都按这个结构回答：业务背景 -> 技术方案 -> 为什么这样做 -> 失败怎么办 -> 如何保证一致性和幂等。

## 五、最终验收清单

第 30 天结束后，必须做到：

1. 2 分钟讲清自我介绍。
2. 15 分钟讲清智能视频内容社区平台。
3. 10 分钟讲清市场交易平台。
4. 20 个必背问题不卡壳。
5. 项目题能主动带出高并发、一致性、幂等、失败补偿。
6. HR 面能回答优缺点、职业规划、为什么选择 Java 后端、反问面试官。

## 六、面试前必背 20 题

1. HashMap 底层原理、扩容、树化条件。
2. ConcurrentHashMap JDK7/JDK8 区别。
3. volatile 的作用，为什么不能保证原子性。
4. synchronized 和 ReentrantLock 区别。
5. 线程池核心参数、执行流程、拒绝策略。
6. AQS 原理。
7. ThreadLocal 内存泄漏。
8. JVM 内存结构。
9. OOM 和 CPU 飙高排查。
10. MySQL B+Tree、回表、覆盖索引。
11. MVCC 和事务隔离级别。
12. Spring IOC、AOP、Bean 生命周期。
13. Spring 事务失效场景。
14. Redis 缓存穿透、击穿、雪崩。
15. Redis 分布式锁和 Lua 原子性。
16. RabbitMQ 可靠性和重复消费。
17. Nacos、Gateway、OpenFeign、Sentinel 分别做什么。
18. 点赞、收藏、投币为什么用 Redis + Lua + MQ。
19. 观看历史为什么用 ZSet。
20. AI 语义搜索完整流程。

## 七、执行提醒

- 不要只默读，必须开口说。
- 不要追求一次背完，先把每题压缩成 1 分钟版本。
- 不会的问题当天记录，第二天先复盘。
- 项目题不要只讲用了什么技术，要讲为什么这么设计。
- 面试官连续追问时，优先回答：异常怎么办、数据怎么一致、重复请求怎么幂等。
