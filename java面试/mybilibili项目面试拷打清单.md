# mybilibili-cloud 项目面试拷打清单

> 本文档模拟 Java 中高级面试官视角，针对 mybilibili-cloud 微服务视频平台项目，按模块和技术栈进行深度追问。
> 每个问题后标注了 **难度等级**：⭐基础 ⭐⭐进阶 ⭐⭐⭐深水区（答不好会被追着打）

## 附录：高频追问连环炮模板

面试官通常会用以下模式连环追问，提前准备：

```
场景 → 方案 → 为什么 → 有什么问题 → 怎么解决 → 还有更好的方案吗？
```

**示例**：
1. 弹幕怎么存的？→ MySQL + Redis
2. 为什么不只用 Redis？→ 持久化考虑
3. MySQL 写入量大怎么办？→ MQ 异步
4. MQ 消息丢了怎么办？→ Confirm + 手动 ACK + 持久化
5. 消息重复了怎么办？→ 幂等设计
6. 幂等的 Key 怎么设计？→ 用户ID + 视频ID + 内容Hash + 时间窗口
7. 还有更好的方案吗？→ ……

> **核心建议**：每个技术选型都要准备好 **"为什么用它"** 和 **"它有什么缺点"** 两个方向的回答。只会说优点不说缺点，面试官会认为你只是在背八股文而没有真正用过。

## 面试准备优先级

根据面试高频考点，建议按以下优先级准备：

| 优先级 | 模块 | 原因 |
|--------|------|------|
| 🔴 P0 | Redis（缓存三连、一致性、分布式锁） | 几乎必问，且容易深追 |
| 🔴 P0 | RabbitMQ（可靠性三板斧、幂等） | 用了 MQ 就必问消息丢失和重复 |
| 🟡 P1 | 微服务架构（拆分、Feign、Gateway） | 考察架构理解和实战经验 |
| 🟡 P1 | 高并发场景（弹幕、点赞、播放量） | 结合简历上的"高并发"关键词 |
| 🟢 P2 | Elasticsearch（索引设计、数据同步） | 搜索是亮点，但不是每个面试官都会问 |
| 🟢 P2 | AI/RAG（完整链路、向量检索） | 技术亮点加分项 |
| 🔵 P3 | 数据库优化（索引、分页、分表） | Java 基本功，结合项目问 |
| 🔵 P3 | 工程能力（部署、日志、压测） | 加分项，体现工程素养 |
